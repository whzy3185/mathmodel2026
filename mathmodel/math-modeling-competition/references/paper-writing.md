# Contest Paper Writing

## Summary

Write last. In one page: define the problem in the team's chosen frame; name the main route; answer every required component with concrete results and units; give the strongest validation/sensitivity evidence; state the recommendation and a material limitation. Avoid background padding, generic “we established a model,” and award language.

## Body contract

Every section must move claim → method/equation → executed result → evidence → interpretation. Put long derivations and code in appendices only if the current rules permit and the body remains self-contained.

- **Problem restatement:** deliverables and dependencies, not copied wording.
- **Assumptions:** necessity, justification, where used, refutation condition.
- **Symbols:** definition, unit, domain, source.
- **Model:** baseline, candidate rejection, formulation, parameters, algorithm.
- **Results:** explicit numbers and uncertainty; solver status where relevant.
- **Validation:** independent evidence and failure boundaries.
- **Strengths/weaknesses:** specific, not ritual phrases.
- **Conclusion:** answer questions; introduce no new evidence.

For MCM/ICM, write in clear English and follow the current official Summary Sheet, anonymity, page, AI and single-PDF rules. For CUMCM, follow the current official format and supporting-material/AI disclosure rules. A Memo/Letter translates validated results into audience-specific action; it does not add unsupported claims.

Maintain a claim–evidence matrix and regenerate numerical statements from structured result files after any model change.
